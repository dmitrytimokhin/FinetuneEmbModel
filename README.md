## Что вообще такое RAG и эмбеддинги

Представьте, что у вас есть тысяча страниц банковской документации и пользователь
спрашивает: «Как досрочно погасить ипотеку?». Перечитывать всё нет смысла.
Нужно **быстро найти** релевантный абзац и отдать его языковой модели (GPT, LLaMA),
которая уже сформулирует ответ. Это и есть **RAG** — Retrieval-Augmented Generation.

**Retriever (он же ретривер)** — компонент, который ищет нужные абзацы.
Он работает через **эмбеддинги**: каждый текст превращается в вектор из ~1024 чисел,
и поиск — это поиск ближайших векторов в пространстве.

Проблема: стандартная модель никогда не видела слов «грейс-период», «ОГРНИП»
или «аннуитетный платёж» в нужном контексте. Её векторное пространство
не приспособлено для банковских документов. Нам нужно **дообучить** (fine-tune) её.

## Как работает ноутбук: шаги пайплайна

```
[1] Генерация корпуса (corpus.csv)
        ↓
[2] Этап 1: TSDAE — доменная адаптация без разметки
        ↓
[3] Генерация триплетов из корпуса
        ↓
[4] Этап 2A: TripletLoss — supervised fine-tuning
[4] Этап 2B: MNRL      — supervised fine-tuning
[4] Этап 2C: TSDAE→MNRL — двухэтапный пайплайн
        ↓
[5] Сравнение всех моделей: Recall@k, MRR, NDCG
```

Каждый шаг — отдельная секция в ноутбуке с объяснением и визуализацией.

## Глобальные параметры (менять только здесь)

В первой ячейке ноутбука:

```python
NUM_EPOCHS_TSDAE        = 30   # эпох для unsupervised прогрева
NUM_EPOCHS_SUPERVISED   = 30   # эпох для supervised fine-tuning
EARLY_STOPPING_PATIENCE = 5    # остановить если N эпох нет улучшения
LOG_EVERY               = "epoch"  # "epoch" или "steps"
```

## Модель

Базовая модель: **[deepvk/USER-bge-m3](https://huggingface.co/deepvk/USER-bge-m3)**
Русскоязычная мультиязычная модель на архитектуре XLM-RoBERTa (≈560M параметров).
Размерность эмбеддинга: **1024**.

## Что показывают метрики

| Метрика | Объяснение | Важность для RAG |
|---------|------------|-----------------|
| **Recall@1** | Правильный ответ попал в топ-1? | Максимальная точность |
| **Recall@5** | Правильный ответ попал в топ-5? | **Главная метрика** для RAG |
| **Recall@10** | Правильный ответ попал в топ-10? | Максимальный охват |
| **MRR@10** | Средняя позиция правильного ответа | Качество ранжирования |
| **NDCG@10** | Учитывает и позицию, и количество | Полная оценка |

Для RAG чаще всего используют **Recall@5** — это означает:
«В 70% случаев правильный абзац оказался среди первых 5 найденных».
