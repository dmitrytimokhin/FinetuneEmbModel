## 1. Зачем вообще дообучать эмбеддинги

Когда пользователь пишет «как снять деньги без процентов с кредитки», он имеет
в виду грейс-период. Стандартная модель `deepvk/USER-bge-m3` обучена на общих
текстах интернета. Она знает слово «грейс-период», но не понимает, что запрос
пользователя и этот термин — одно и то же в банковском контексте.

Дообучение — это не «переобучение с нуля», а **тонкая настройка** уже умной модели
на конкретную предметную область. Мы берём готовую нейронную сеть весом ~2 ГБ
и «досказываем» ей: «вот как в банковских документах связаны вопрос и ответ».

**Три проблемы, которые решает дообучение:**

| Проблема | Пример | Что происходит без дообучения |
|----------|--------|-------------------------------|
| **Domain shift** | «ПСК», «АСВ», «РКО» | Модель не понимает аббревиатуры |
| **Lexical gap** | Запрос: «снять без процентов» → Doc: «грейс-период» | Разные слова = далёкие векторы |
| **Confusion** | Ипотека vs. автокредит | Похожие документы → одинаковые эмбеддинги |

## 2. Архитектура пайплайна

```
Банковские тексты (corpus.csv)
    │
    ├──► [Этап 0] EDA: длины, топ-слова, примеры шумирования
    │
    ├──► [Этап 1] TSDAE: unsupervised доменная адаптация
    │              Входные данные: только тексты, без разметки
    │              Результат: model_tsdae/  ← знает банковский язык
    │
    ├──► [Этап 1.5] Генерация триплетов
    │              TripletSampler: adjacent | section | query_template
    │              BM25HardNegativeMiner: hard negatives
    │              Результат: train_df (anchor, positive, negative)
    │
    ├──► [Этап 2A] TripletLoss: supervised fine-tuning
    ├──► [Этап 2B] MNRL: supervised fine-tuning  ← рекомендован
    ├──► [Этап 2C] TSDAE → MNRL: двухэтапный пайплайн ← лучший
    │
    └──► [Оценка] RetrievalEvaluator
                  Recall@{1,3,5,10}, MRR@10, NDCG@10, MAP@10
                  Сравнение baseline vs. всех дообученных моделей
```

## 3. Данные: как устроен корпус

### 3.1 Что хранится в corpus.csv

```
sentence   | doc_id        | section                     | chunk_id
───────────────────────────────────────────────────────────────────
Ипотечное  | doc_mortgage  | Ипотека                     | doc_mortgage_p0000
кредитование...
Процентная | doc_mortgage  | Ипотека                     | doc_mortgage_p0001
ставка по...
Дебетовая  | doc_cards     | Банковские карты             | doc_cards_p0000
карта...
```

**15 документов**, ~120–150 чанков. Темы намеренно «путающиеся»:

| Группа | Документы | Сложность для модели |
|--------|-----------|----------------------|
| Кредиты | Ипотека, Автокредит, Потребкредит, Кредиты МСБ | Все говорят о «ставке» и «погашении» |
| Страхование | Имущество, Жизнь | Ипотека тоже страхуется → путаница |
| Сбережения | Вклады, Накопительные счета | Оба говорят о процентах |
| Инвестиции | Брокеридж, Валюта | Оба говорят о «доходности» |
| Бизнес | РКО, Факторинг, Гарантии, Лизинг | Все про «документы» и «ставку» |

Смысл: если модель не может отличить «ставку по ипотеке» от «ставки по факторингу»
— она плохо обучена. Такие «трудные» данные дают максимальный прирост качества.

### 3.2 Как генерируются триплеты

Триплет = три текста: (anchor, positive, negative).

**Идея**: обучить модель так, чтобы `sim(anchor, positive) >> sim(anchor, negative)`.

```python
# Пример триплета с query_template:
anchor   = "Каковы условия досрочного погашения ипотеки?"
positive = "Досрочное погашение ипотеки разрешено без штрафных санкций..."
negative = "Досрочное погашение потребительского кредита также не облагается..."
#                                                           ↑ труднее всего!
```

**Три стратегии** в `TripletSampler`:

```
ADJACENT       anchor = чанк_i,  positive = чанк_{i±1} того же документа
               Работает для линейных текстов. Для банковских — осторожно.

SECTION        anchor и positive — из одной именованной секции документа
               Надёжнее: все чанки в секции «Ипотека / Ставки» релевантны.

QUERY_TEMPLATE anchor = шаблонный запрос ("Что такое {тема}?")
               positive = исходный чанк
               Лучшая стратегия: нет false positives по определению.
```

**BM25 Hard Negatives**: негатив ищется не случайно, а через BM25 — алгоритм
лексического поиска. Находим чанки, лексически похожие на anchor, но из другого документа.
Это «трудные» негативы: они выглядят как ответ, но не являются им.

## 4. Функции потерь: что это и зачем выбирать

Функция потерь (loss) — это число, показывающее «насколько модель ошиблась».
Обучение = минимизация этого числа.

### 4.1 TripletLoss

```
L = max(0,  d(anchor, positive) − d(anchor, negative) + margin)
```

**Перевод на русский**: потеря равна нулю, если расстояние до позитива
меньше расстояния до негатива как минимум на `margin`. Иначе — штраф.

- `margin = 0.5` — «насколько уверенно» модель должна разделять.
- Большой margin → агрессивное обучение, риск переобучения.
- **Минус**: каждый триплет несёт информацию о только одном негативе.

### 4.2 MultipleNegativesRankingLoss (MNRL) ⭐

```
L = −log( exp(sim(a_i, p_i) / τ) / Σ_j exp(sim(a_i, p_j) / τ) )
```

**Перевод**: это кросс-энтропийная потеря. Модель должна «выбрать» правильный
позитив среди всех позитивов в батче. Это **ранжирование**, а не просто отступ.

- `τ (temperature) = 0.05` — масштабирует скоры. Меньше τ → резче разделение.
- При `batch_size = 32` → 31 негатив на запрос **автоматически** (in-batch negatives).
- **Плюс**: не нужны явные негативы. Чем больше батч — тем лучше обучение.

**Почему MNRL лучше TripletLoss**: каждый обучающий шаг несёт информацию
о (batch_size − 1) негативах вместо одного. Информация плотнее.

### 4.3 TSDAE (Denoising Auto-Encoder) — без разметки

```
Corruption: "Ипотека позволяет приобрести жильё в кредит"
      ↓  (удаляем 60% слов случайно)
Input:    "позволяет жильё кредит"
      ↓  encoder → вектор
Output:   "Ипотека позволяет приобрести жильё в кредит"  ← модель восстанавливает
```

**Суть**: модель учится из зашумлённой версии текста восстанавливать оригинал.
Для этого encoder должен «понять» смысл, а не просто запомнить слова.

**Зачем нужен**: TSDAE не требует разметки — только тексты. Он «прогревает» модель
на банковском языке перед этапом с триплетами. Это называется доменной адаптацией.

**Важно**: в версиях `transformers >= 5.0.0` оригинальный TSDAE (seq2seq) не работает
с encoder-only моделями. Мы используем SimCSE-стиль: пары (зашумлённый → оригинал)
с MultipleNegativesRankingLoss. Эффект аналогичный.

## 5. Ранняя остановка: зачем и как работает

Без ранней остановки модель обучается все `num_epochs` эпох, даже если качество
начало деградировать с 8-й эпохи. Мы добавляем автоматическую остановку:

```
Эпоха 1:  loss = 2.14  → новый лучший, сохраняем модель
Эпоха 2:  loss = 1.87  → новый лучший, сохраняем модель
Эпоха 3:  loss = 1.91  → нет улучшения (1/5)
Эпоха 4:  loss = 1.90  → нет улучшения (2/5)
Эпоха 5:  loss = 1.95  → нет улучшения (3/5)
Эпоха 6:  loss = 1.93  → нет улучшения (4/5)
Эпоха 7:  loss = 1.94  → нет улучшения (5/5) → СТОП
→ Загружаем модель из эпохи 2
```

**Параметр**: `EARLY_STOPPING_PATIENCE = 5` (глобально в ноутбуке).

- **Supervised** (с eval): мониторится `eval_loss` через `EarlyStoppingCallback`.
- **Unsupervised** (TSDAE): мониторится `train_loss` через `_EarlyStoppingOnTrainLoss`.

## 6. Метрики оценки

После обучения запускается `RetrievalEvaluator`, который:

1. Кодирует все чанки корпуса → матрица эмбеддингов
2. Кодирует все запросы (anchors из eval)
3. Для каждого запроса находит top-k ближайших чанков
4. Считает попадания

```python
# Recall@5 = 0.72
# Означает: в 72% случаев правильный чанк оказался в топ-5
```

| Метрика | Формула | Приоритет |
|---------|---------|-----------|
| **Recall@1** | % запросов, где правильный ответ на 1-м месте | ⭐⭐ |
| **Recall@5** | % запросов, где правильный ответ в топ-5 | **⭐⭐⭐** |
| **Recall@10** | % запросов, где правильный ответ в топ-10 | ⭐⭐ |
| **MRR@10** | Среднее 1/rank первого правильного ответа | ⭐⭐⭐ |
| **NDCG@10** | Учитывает позицию и количество правильных | ⭐⭐ |

**Для RAG Recall@5 — главная метрика**: LLM читает top-5 чанков, и если
правильный не попал в них, никакая языковая модель не поможет.

## 7. Двухэтапный пайплайн (лучшая практика)

```
Этап 1 — TSDAE (unsupervised, только тексты)
    Цель: адаптировать пространство эмбеддингов к банковскому языку
    Данные: corpus.csv, ~150 чанков
    Время: ~10–20 эпох с early stopping

Этап 2 — MNRL (supervised, триплеты)
    Цель: научить различать релевантный/нерелевантный ответ
    Данные: train_df с BM25-hard negatives, ~600–1000 триплетов
    Время: ~15–25 эпох с early stopping

Результат: TSDAE+MNRL превосходит только MNRL на +5–15% Recall@5
```

**Почему так работает**: TSDAE — это как «языковой курс» перед «профессиональным
экзаменом». Сначала модель учит банковские слова и понятия, потом учится находить
правильные ответы. Каждый этап решает свою задачу.
